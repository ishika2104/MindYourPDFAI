# Deployment

MindYourPDF ships on **Lovable** — the entire stack (Cloudflare Worker SSR + Supabase Postgres/Storage/Auth + AI Gateway) is provisioned and deployed from the Lovable editor. There is no separate infra to configure.

## Publishing

1. In the Lovable editor, click **Publish** (top-right).
2. Pick a project subdomain, or attach a **custom domain** under Settings → Domains.
3. Preview is available at `https://<project>-<id>.lovable.app` immediately; production URL becomes live on publish.

Every published build regenerates the Cloudflare Worker bundle, uploads it, and points the domain at the new deployment atomically.

## Environments

| Env      | URL                                            | Data           |
| -------- | ---------------------------------------------- | -------------- |
| Preview  | `project--<id>-dev.lovable.app`                | Shared with prod |
| Prod     | `project--<id>.lovable.app` or custom domain   | Same DB        |

There is a **single Supabase project** backing both — treat migrations as prod-affecting.

## Environment variables

Managed automatically by Lovable Cloud. You never edit `.env` in production.

**Client (`import.meta.env`)** — safe to bundle:
- `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`

**Server (`process.env`)** — read inside handlers only:
- `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
- `LOVABLE_API_KEY` — AI Gateway

Never rename service-role secrets to `VITE_*` — that would leak them to browsers.

## Database migrations

- Author migrations through the Lovable migration tool — never `psql` directly.
- Every `CREATE TABLE public.*` **must** ship with `GRANT`s in the same migration or PostgREST returns permission errors.
- RLS is required on every user-data table with policies scoped to `auth.uid()`.

## Storage

- Bucket: `pdfs` (private).
- Object path: `{user_id}/{uuid}-{sanitized_filename}`.
- Signed URLs generated by server functions when a viewer needs read access.

## Third-party keys

Only the **Lovable AI Gateway** key is required — it fronts Gemini, OpenAI TTS, and embeddings under one billing surface. No OpenAI / Anthropic / Google keys to add.

If a user brings their own provider (unusual), add secrets via the Lovable **Secrets** panel — they land in `process.env` for server-only code.

## Post-deploy checklist

- Run **Security scan** (Lovable → Security) — resolve any critical / high findings.
- Run **Supabase linter** — index recommendations and RLS coverage.
- Confirm **Google OAuth** is enabled under the auth provider settings (required for Google sign-in).
- Set app-specific SEO in the root route `head()` (title, description, `og:image` on a stable https URL).
- Smoke test: sign-in → upload → chat → summary → export.

## Rollback

Every published deploy is retained. In Lovable → Deployments, select any past build and click **Restore** — the Worker is re-pinned in seconds. The database is **not** rolled back; write a compensating migration if a schema change needs reverting.
